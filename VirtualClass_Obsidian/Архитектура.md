# Архитектура проекта VirtualClass

## Обзор

VirtualClass — это платформа для управления учебными классами и курсами. Система состоит из веб-приложения с REST API бэкендом и SPA фронтендом, развёрнутых через Docker Compose с инфраструктурой на AWS (Terraform + Ansible).

## Архитектурные паттерны

### Бэкенд: Модульный монолит

Каждая предметная область — самостоятельный NestJS модуль с контроллером, сервисом и DTO:

| Модуль | Ответственность |
|--------|---------------|
| `UsersModule` | Аутентификация, CRUD пользователей |
| `ClassesModule` | Управление классами/курсами |
| `MaterialsModule` | Управление материалами + загрузка файлов |
| `AiModule` | ИИ-чат через Ollama |
| `AdminModule` | Панель администратора (запись групп, списки преподавателей) |
| `PrismaModule` | Глобальный сервис Prisma ORM (`@Global()` декоратор) |

### Фронтенд: Компонентный SPA с контекстным состоянием

- **Нет маршрутизатора** — навигация через `activeTab` внутри `App.tsx`
- **Три роли**: Admin, Teacher, Student — каждая рендерит свой интерфейс
- **Управление состоянием**: React Context API (3 провайдера)

### Поток запросов (Production)

```
Браузер → Nginx (порт 80)
  ├── /api/users/login  ──rate-limit──►  Backend:3001/users/login
  ├── /api/*             ──────────────►  Backend:3001/*
  └── /*                 ──────────────►  Frontend:4173 (Vite preview)
```

### Поток запросов (Development)

```
Браузер (порт 5173)
  Vite Dev Server
  ├── /api/*  ──proxy──►  Backend:3001
  └── /*      ─────────►  React SPA (hot reload)
```

## Ролевая модель

| Роль | Возможности |
|------|------------|
| **admin** | Панель администратора: управление классами, запись групп, список преподавателей |
| **teacher** | Дашборд, курсы, материалы, ИИ-генератор заданий, студенты, отправки |
| **student** | Дашборд, курсы, ИИ-ассистент, материалы, задания, профиль |

## Безопасность

| Мера | Описание |
|------|----------|
| Хеширование паролей | bcrypt, 10 раундов |
| Rate limiting | Nginx: 5 запросов/мин на `/api/users/login` |
| Fail2ban | Бан IP на 2 часа при повторных 401/403 |
| Firewall (UFW) | Открыты только порты 80, 443, 2222 |
| SSH | Только по ключам, порт 2222 |

> **Внимание**: На текущий момент бэкенд не имеет JWT/сессионной авторизации. Аутентификация — только email/password с возвратом объекта пользователя. Роли проверяются только на клиенте.
